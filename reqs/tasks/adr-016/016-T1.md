# 1. Goal & Context

## SMART Goal

`L1AutomationUseCase.get_labels` を修正し、`adr-` (arch) と `design-` (spec) の両方のプレフィックスに対応させ、それぞれの初期フェーズ ラベルを正しく返却できるようにする。

## As-is

現状の `get_labels` は `adr-(\d{3})` のみを正規表現で検索しており、`design-` プレフィックスを処理できない。また、全ての L1 Issue に対 して一律で `arch` ラベルを付与する前提となっている。

## To-be

`L1AutomationUseCase.get_labels` が以下の挙動を示す：

- `adr-XXX` -> `['adr:XXX', 'L1', 'arch', 'plan']` を返す。
- `design-XXX` -> `['design:XXX', 'L1', 'spec', 'plan']` を返す。

## Design Evidence

- `reqs/design/_approved/adr-016.md`
- `reqs/context/adr-016/context-map.md`

# 3. Implementation Steps & Constraints

## Steps

1. `tests/unit/usecase/test_l1_automation_usecase.py` に、`design-XXX` 形式の ID に対するテストケースを追加する（Red）。
2. `L1AutomationUseCase.get_labels` の正規表現を `(?:adr|design)-(\d{3})` に更新する。
3. ID のプレフィックス（`adr` か `design` か）を判定し、初期フェー ズ（`arch` または `spec`）をリストに含める。
4. `plan` ラベルを常時リストに含める。
5. テストを実行し、パスすることを確認する（Green）。

## Constraints

- 既存の `adr:XXX` ラベルの生成ロジックを壊さないこと。
- `adr:design-016` のような不正なラベルを生成しないよう、プレフィックスを正確に分離すること。
