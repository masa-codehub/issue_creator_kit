# 1. Goal & Context

## SMART Goal

`RelayEngine` において、`integration` + `audit` タスクが完了した際 、上位の ADR/DesignDoc Issue のフェーズを適切に遷移（例：arch -> spec）させるロジックを実装し、テストで検証する。

## As-is

現状の `RelayEngine` は下位のタスク更新のみを担当しており、上位 Issue へのフェードバックやラベルのフェーズ遷移機能を持っていない。

## To-be

- `RelayEngine.execute_relay` がクローズされたタスクを判定し、`integration` かつ `audit` ラベルがある場合に `_handle_phase_transition` を呼び出す。
- `_handle_phase_transition` が上位 Issue のラベルを取得し、`arch` -> `spec` -> `tdd` の順序で安全に遷移（PUT による置換）を行う。
- 遷移先のフェーズが現在のフェーズより進んでいる場合のみ更新を行う 「冪等性ガード」を備える。

# 3. Implementation Steps & Constraints

## Steps

1. `tests/unit/usecase/test_relay_engine_phase.py` を作成し、各種フェーズ遷移と冪等性ガードのテストケースを記述する（Red）。
2. `RelayEngine` にフェーズ順序を定義する定数 `PHASE_ORDER = ["arch", "spec", "tdd"]` を追加する。
3. `RelayEngine._handle_phase_transition(source_task, source_labels)` を実装する。
   - `source_task.parent` から上位 Issue No を特定。
   - 上記の現在のラベルを取得。
   - `integration(arch+audit)` 完了なら `spec` へ、`integration(spec+audit)` なら `tdd` へ遷移。
   - その他のラベル（`L1`, `adr:NNN` 等）を保持しつつ、フェーズラベルのみを置換。
   - 遷移先が現在より前のフェーズなら更新をスキップ。
4. `RelayEngine.execute_relay` に、`source_task.type == "integration"` かつ `"audit" in source_labels` の条件分岐を追加する。
5. テストを実行し、パスすることを確認する（Green）。

## Constraints

- 上位 Issue の `L1` や `adr:XXX` ラベルを誤って消去しないこと。
- `audit` ラベルがない `integration` タスクは遷移をトリガーしないこと。
